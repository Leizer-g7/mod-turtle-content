# mod-turtle-content

Turtle WoW content (zones, NPCs, quests, items, loot, objects) for AzerothCore 3.3.5a, built one zone at a time.

Built for the ScourgeLands server:
- Core: Grimfeather/azerothcore-wotlk `b4bbae96` with mod-playerbots
- Source data: the Tortoise-WoW world database from `tortoise-wow-main-pengle` (`sql/create_databases.sql` + `sql/base` + every `sql/database_updates/world` update up to 2026-09-16), and that repo's C++ scripts

## Install

Three parts, in this order. The server parts need the worldserver stopped.

**1. Client patch** (every player's 3.3.5 client)
- Run `client/JOIN_PATCH.bat` to put `patch-y.mpq` back together from its parts.
- Leave `Data\patch-z.mpq` in place: it holds the world-map work made by hand on the server PC (continent hover grid `Azeroth.zmp`, the Balor island drawing, Turtle's Arathi map and its `WorldMapOverlay.dbc`). It loads after `patch-y`, so its `WorldMapOverlay.dbc` wins; world-map overlays a new build adds stay hidden until the converter makes the world-map work itself.
- Copy `client/patch-y.mpq` into the client's `Data` folder, replacing the old `patch-y.mpq`.
- Run `client/CHECK_CLIENT.bat` and give it the client's `Data` folder. It changes nothing. It reports any archive that overrides the patch (today: `patch-z` replaces `WorldMapOverlay.dbc`, expected) and any client table that differs from the copy the patch was built on (the patch would hide that patch's rows).
- Delete the client's `Cache` folder.
- The patch (about 250 MB, in 10 parts) contains Turtle's terrain, buildings and textures, Turtle's reputations, minimap images (one per new-zone tile), grass for the Turtle ground textures, world-map images, the new zones and subzones, the Stormwrought Ruins, Gilneas City, Dragonmaw Retreat, Windhorn Canyon and Crescent Grove maps, the Stormwind Vault dungeon, flight paths, area triggers, sky/fog lighting, object models and the custom items. Every table in it is built from the copy your client already uses, so your other client patches keep working.

**2. Server map data** (once per terrain change, and after any change to the buildings: the collision data must lose the old lava)
- Run `server-data/install_server_data.bat` and type `YES` when asked. It:
  1. Checks the client has every model and texture the new tiles use.
  2. Rebuilds collision data (vmaps) with AzerothCore's own tools, from a hard-linked copy of the client plus `patch-y`. This takes 30–60 minutes.
  3. Rebuilds pathing (mmaps) for the Turtle tiles and the tiles around them.
  4. Backs up, then replaces the data in `Acore Data`: the 343 map tiles in `server-data/maps/` (Arathi, Balor, Northwind, Grim Reaches, Gilneas, Gillijim's Isle, Lapidis Isle, Tel'Abim, Mount Hyjal, the Wetlands, Stranglethorn's Bloodsail Retreat, Azshara's two new camps, Stormwind's Davenburg, the Windhorn camps and canyon entrance in Thousand Needles, Sorrowguard Keep in the Swamp of Sorrows, Turtle's Stonetalon, Turtle's Badlands, Turtle's eastern Feralas, Felwood's Talonbranch Glade, Ashenvale's Forest Song camp and Crescent Grove cave, Dustwallow's Westhaven Hollow, maps 818, 815, 816, 820 and 802), the vmaps folder, and the rebuilt mmaps (maps 0 and 1 around the Turtle tiles, and all of maps 818, 815, 816, 820 and 802).
- The backup goes to `Acore Data\backup_before_turtle_<date>` and includes a `RESTORE.bat`.
- The paths it uses are at the top of `install_server_data.py`.

**3. Module**
1. Copy this folder to `azerothcore-wotlk/modules/mod-turtle-content`.
2. Re-run CMake and rebuild the core. The module adds one small script, which logs what's loaded at startup.
3. Copy `conf/mod_turtle_content.conf.dist` next to your other module configs. The worldserver also runs without it.
4. **Back up `acore_world`**, then start the worldserver.
   - The AzerothCore DB updater applies everything in `data/sql/db-world/` automatically. The world database must be in `Updates.EnableDatabases`, which it is by default.
   - When a file changes, the updater re-applies it. Every file deletes its own rows first, so re-running is safe.

On startup you should see:
`>> mod-turtle-content: 12104 creatures and 9154 gameobjects from Turtle WoW are loaded`

**To remove a zone,** run its file from `sql_rollback/` and delete its file from `data/sql/db-world/`. The rollback files are never applied automatically. For the terrain, run `RESTORE.bat` from the backup folder and put the previous `patch-y.mpq` back.

Some Turtle quests are given or taken by NPCs that 3.3.5 already has. When such an NPC has no quest-giver flag in 3.3.5 (Lord Falconcrest, Anduin Wrynn, Avette Fellwood, Slagg), the zone file adds it and its rollback file restores the original flags.

Creature, quest and gameobject entries keep their Turtle IDs. Every one is checked against your `acore_world`, and none collide so far.

Items are different: Turtle numbered its own items (Balor quest items, keys, dungeon drops) with ids that 3.3.5 uses for Wrath gear. The build compares names. If the names are close, the item is the same one renamed by Blizzard and the 3.3.5 item is used. If 3.3.5 moved the item to a new id (the TBC throwing weapons, whose old ids are now "Broken …" junk), the new 3.3.5 item is used. Otherwise the Turtle item gets id 1,000,000 + its Turtle id, with its own Item.dbc row in the client patch. `check.py` reports any module item whose 3.3.5 item is a different one.

## Terrain modes

Turtle reshaped parts of the existing world. In Arathi, Wildtusk Village and the Ruins of Zul'Rasaz are carved out of mountains that are cliffs on a stock 3.3.5 client. Each zone has a `terrain` setting:

- **`turtle`** (Arathi now): Turtle's map tiles go into the client patch and the server map data. Spawns keep Turtle's exact positions and nothing is held back.
- **`turtle` with `merge_region`** (Northwind): for map tiles Turtle shares with live 3.3.5 land. Each tile stays the 3.3.5 one and only some 33-yard chunks come from Turtle: the chunks Turtle marks as the zone, and the chunks where Turtle reshaped the ground (those keep their 3.3.5 area). The edges where the two meet are then made to line up exactly. 3.3.5 buildings (Stormwind City, the harbor) are kept, and Turtle's are added where they stand. With `"reshaped": "connected"` (Grim Reaches) only reshaped ground that touches the zone is taken, so Turtle's unrelated edits in the same tiles (Badlands, Grim Batol) stay 3.3.5. With `"reshaped": "sea"` (Gillijim's Isle, Turtle land on deep 3.3.5 sea) only the sea bed around the zone is added, never a neighbouring Turtle zone; tiles 3.3.5 does not have at all are built on a copy of a stock open-sea tile (`ocean_base`), and at the seams the 3.3.5 sea floor rises to meet Turtle's ground (`stitch_onto: donor`).
- **`stock`**: for zones whose tiles aren't converted yet. Spawns are placed on the stock 3.3.5 ground. Subzones listed in `hold_until_terrain_patch` are held back, along with their NPCs, objects and quests.

The tiles are cleaned up for 3.3.5 when they're converted:
- broken empty-liquid offsets (these crash AzerothCore's map extractor)
- water layers that Turtle's tools duplicated up to 32 times
- Turtle's object IDs, which are moved to a reserved range so they can't clash with neighbouring stock tiles
